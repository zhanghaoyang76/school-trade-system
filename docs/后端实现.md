# 后端实现与验证

Java 21、Spring Boot 3.5.16、MyBatis Plus 3.5.18。MySQL数据库 `2024011490`，H2仅为test依赖。

ApiController、AdminController、FileController只适配HTTP。对应EndpointService分发业务，AccountService、CatalogueService、TradeService、AdminService、FileService处理业务与资源归属。mapper/Store是持久层门面，委托真正的MyBatis SqlMapper执行SelectProvider/InsertProvider/UpdateProvider，SqlProvider把应用内SQL中的问号转换为绑定参数；SQL文本不接收客户端输入。ProductsMapper实际使用BaseMapper插入和更新商品，CatalogueMapper.xml实际执行动态类别/名称搜索及价格、销量、好评率关联排序。数据库有17张表，对应实体均在entity目录。

从backend目录启动：填写已忽略的config/application-local.properties中的spring.datasource.url/username/password，以及market.admin.username/password；也支持MARKET_ADMIN_USERNAME/PASSWORD环境变量。初始密码至少8位，仅在库中没有管理员时创建，不覆盖已有密码。执行`mvn package`后`java -jar target/market-1.0.0.jar`，或`mvn spring-boot:run`。默认8080，前端代理/api。数据库脚本database/schema.sql创建指定数据库；应用幂等执行classpath schema.sql建表。首次仅建立类别、平台托管/手续费账户、用户配置的管理员。

结账：钱包可用→平台托管；收货：托管→卖家冻结+手续费；满24小时：卖家冻结→可用，同时解冻买家奖励积分。售后通过立即冲回冻结收入和手续费、退实付与原抵扣积分、取消奖励积分；交回才恢复库存。订单保存商品、费率、买家/卖家/店铺名称快照。所有资金状态转换同一事务完成，流水业务键唯一。

这个单节点课程项目在每个资金事务开始先锁定平台ESCROW行，刻意串行化资金转换以保证一致的锁顺序，随后再锁用户、商品与钱包；商品按编号排序。管理员关店、商品审核及商品保存共用该锁顺序。这是理解简单、资金一致的实现选择，不宣称高吞吐。定时任务每分钟扫描，7天自动收货和24小时解冻共用人工操作服务；重复处理保持幂等。等级自动更新使用`WHERE level_mode='AUTO'`保护管理员手动覆盖。

Session仅存身份；拦截器重新校验审核、删除状态；修改请求必须有X-CSRF-TOKEN。退出后会话失效，应重新获取CSRF。上传解码校验后重编码为PNG并随机命名，证件只允许本人、本人注册会话或管理员访问。AOP仅记录成功操作、对象编号与变更字段名，参数值不入日志。

2026-11-13实际验证：先编写MarketTest再运行Maven，最初因默认仓库写权限和网络失败，不能认作业务RED。依赖下载期间实现代码并补充测试，不声称严格逐功能TDD。首次可执行测试14项均出现H2多生成键启动错误，修复为指定id；切换真实MyBatis持久层时出现2项空聚合结果错误，配置空行实例和null字段后修复。后续25项测试全部通过（3账户/商品，4基础HTTP，5安全/分页，13交易）。测试包括跨店失败回滚、结账幂等、并发最后一件、积分分摊、费率退款、7天/24小时边界、售后重提、重复任务、逻辑删除、私有证件、后台越权、数量溢出、删除卖家防御、订单快照、并发手动等级保持。

本机命令使用`mvn -Dmaven.repo.local=backend/.m2 -f backend/pom.xml test`（从项目根目录，实际本地仓库参数为绝对路径），真实结果见target/surefire-reports。打包曾因Windows运行中的JAR被占用失败，停止进程后重打包成功。已使用本地配置启动真实MySQL，HTTP `/api/categories`返回6类别、`/api/auth/csrf`返回令牌；没有将H2结果冒充MySQL交易验证。完整浏览器交易联调由项目主任务继续记录。
