# 整体设计

## 当前状态

本文件为设计阶段过程说明。业务规则详见《需求确认记录》；模块划分和整体数据流程已获确认，之后已完成应用实现与核心验证，结果见《联调与测试》。

## 已确认的技术方案

- Java 21、Spring Boot 3.5.x、MyBatis Plus，复杂查询使用MyBatis XML。
- Vue 3、Vite、Element Plus。
- MySQL 8.0，数据库名2024011490。
- 一个前端、一个后端、一个数据库，图片本地存储；Controller → Service → Mapper分层。
- Session登录，通过Cookie传递会话标识；后端校验身份和权限。
- Spring定时任务处理自动收货、冻结解除及商家等级更新。
- 具体补丁版本在初始化前锁定并记录；上述技术组合已获用户确认。

## 已确认模块划分

| 模块 | 职责 | 主要依赖 |
|---|---|---|
| 账号与权限 | 验证码、注册、登录、资料、注册审核、角色权限 | 用户、Session、图片存储 |
| 商品与店铺 | 多图发布、审核、上下架、分类、搜索排序、店铺商品 | 用户、店铺、商品、评价统计 |
| 购物车与订单 | 跨店选购、统一结账、拆单、库存锁定、交易约定、取消、交付 | 商品、钱包、积分、黑名单 |
| 钱包与结算 | 管理员充值、买家扣款、中间账户、卖家冻结收入、手续费、解冻 | 订单、钱包流水、商家等级 |
| 积分与售后 | 积分获取与抵扣、24小时退货、即时退款、退货交回 | 订单明细、钱包、库存 |
| 评价与等级 | 商品五星及文字、服务态度、卖家评价购买者、好评统计及等级调整 | 完成的交易、用户、店铺 |
| 后台管理 | 审核、用户管理、充值、等级与手续费展示、关店、平台拉黑 | 以上业务服务 |

以上是同一应用中的业务模块，不是独立微服务。后台复用业务服务，避免重复编写扣款、退款等规则。

## 已确认前后端数据流

1. Vue页面通过HTTP访问REST接口，携带Session Cookie。
2. 权限拦截器识别登录身份并检查接口角色权限；Service继续核对资源归属及交易资格。
3. Controller接收并校验参数，调用Service；Service执行规则及数据库事务。
4. Mapper使用BaseMapper及XML查询访问MySQL；Entity对应数据库实体。
5. Controller将结果返回前端，统一异常处理将失败转为一致的响应，页面展示结果。
6. 图片上传进入后端校验后存储本地，数据库保存图片引用；证件图片的访问需权限控制。

## 已确认交易流程

购物车结账 → 校验身份、店铺、拉黑、库存、钱包、积分 → 按卖家拆单 → 同一数据库事务扣款扣积分扣库存并记录托管 → 分订单约定线下交付 → 卖家标记交付 → 买家主动确认或7天自动确认 → 按下单费率结算，收入及新积分冻结24小时 → 无售后则解冻。

交付前取消：退回钱包款和抵扣积分、恢复库存。收货24小时内申请退货：冻结持续保留；卖家审核通过立即退款，冲回手续费及对应积分，标为在途退货；卖家确认收到后恢复库存，标为已退货。

## 已确认一致性与验证原则

- 结账失败时整体回滚，避免扣款成功但订单或库存失败。
- 扣库存、扣钱包必须在数据库层进行余额或数量条件检查，不能只依赖页面或先查后改。
- 确认、取消、退款、自动处理须避免重复扣款或重复结算；人工操作和定时任务竞争时只允许一个状态转换成功。
- 后端验证注册审核、资源归属、关闭店铺及拉黑限制。
- 核心验证覆盖注册审核、跨店结账回滚、并发库存、资金和积分流向、7天自动收货、24小时边界、退款及恢复库存、等级覆盖、关店和拉黑。
- 实际测试命令、结果及问题在实施阶段记录，目前尚未执行应用测试。
